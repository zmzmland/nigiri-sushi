# にぎり寿司 — アプリケーション化の手順

配布先: 他の Mac にも配る / 起動はダブルクリック1つ

---

## 0. 全体像

このゲームは **Unity 本体** と **画像認識（Python）** の2プロセスで動きます。
片方だけでは成立しないので、配布物は両方を含んだ1つのフォルダにします。

```
にぎり寿司/
    にぎり寿司.app          ← Unity のビルド
    セットアップ.command     ← 初回のみ実行（ライブラリを入れる）
    はじめる.command         ← 毎回これをダブルクリック
    カメラを選ぶ.command     ← カメラがずれたとき
    はじめにお読みください.txt
    ImageSearch/
        main.py
        camera_pick.py
        camera_check.py
        compare_models.py
        config.example.json
        requirements.txt
        data.yaml
        runs/detect/train-6/weights/best.pt
        .venv/               ← セットアップ.command が作る
```

`.command` は macOS でダブルクリックすると実行できるシェルスクリプトです。
ターミナルが自動で開き、そこに認識の状況やエラーが出ます。

---

## 1. 【先に必須】ゲーム画面から判定できるようにする

**現状のままアプリ化すると詰みます。**

判定の Space キーは OpenCV のカメラウィンドウでしか効きません。
ゲームをフルスクリーンにすると、プレイヤーはそのウィンドウに触れられず、
永久に判定できなくなります。

対処として `CaptureTrigger.cs` を復活させました。ゲーム画面で Space を押すと
`capture_trigger.txt` が書かれ、Python 側がそれを検知して判定します。
カメラウィンドウでの Space も従来どおり効くので、動作確認は今までどおりできます。

### Unity での作業

1. **Game Scene** を開く
2. Hierarchy の空いているところで右クリック → **Create Empty**
3. 名前を `CaptureTrigger` にする
4. Inspector の **Add Component** → `CaptureTrigger` を選ぶ
5. `Cmd + S` で保存
6. **Game Scene 2** でも 2〜5 を繰り返す

両方のシーンに必要です。1面だけだと2面で判定できません。

---

## 2. 【必須】終了手段を用意する

フルスクリーンのビルドには終了手段が要ります。`Cmd + Q` でも閉じられますが、
来場者が誤って押す事故を避けたいので、**ESC の長押し（2秒）** にしました。

押している間、画面下部にバーが伸びて進捗が見えます。

### Unity での作業

1. **SampleScene**（タイトル）を開く
2. Hierarchy で右クリック → **Create Empty**
3. 名前を `QuitHandler` にする
4. **Add Component** → `QuitHandler`
5. `Cmd + S`

`DontDestroyOnLoad` でシーンをまたいで生き残るので、**タイトルに置くだけで
全シーンで効きます。** 各シーンに置く必要はありません。

長押しの秒数は Inspector の `Hold Seconds` で変えられます。

---

## 3. Build Settings を整える

**File → Build Settings**（新しい Unity なら **File → Build Profiles**）

### シーンの登録

`Scenes In Build` に5つ全て入っていることを確認します。**順番が重要**で、
**一番上（index 0）が起動時に開くシーン**になります。

```
0  Scenes/SampleScene      ← タイトル。必ず先頭に
1  Scenes/Game Scene
2  Scenes/WaitScene
3  Scenes/Game Scene 2
4  Scenes/ResultScene
```

足りないものは Project ウィンドウからドラッグして追加し、
ドラッグで順番を入れ替えます。

### プラットフォーム

`macOS` を選び、**Switch Platform**。既に macOS ならそのままです。

**Architecture** は **Intel 64-bit + Apple Silicon**（Universal）を選びます。
配布先の Mac が Intel か Apple Silicon か分からないので、両対応にしておきます。

---

## 4. Player Settings

Build Settings の **Player Settings...** から開きます。

| 項目 | 設定 | 理由 |
|---|---|---|
| Company Name | 学校名や班名 | `.app` の識別子に使われます |
| Product Name | `にぎり寿司` | アプリ名として表示されます |
| Version | `1.0` | |
| Default Is Full Screen | ✅ オン | 展示用 |
| Default Screen Width / Height | `1920` / `1080` | |
| Mac Retina Support | ✅ オン | 文字がぼやけません |
| Resizable Window | オフ | 展示中に崩されないように |
| Display Resolution Dialog | 無し / Disabled | 起動時の設定画面を出さない |

**Icon** も設定できます。`Title.png` などを指定すると Dock やアイコンに反映されます。

---

## 5. ビルドする

1. **Build**（`Build And Run` ではなく `Build`）
2. 保存先を聞かれるので、**新しい空フォルダ**を作って選ぶ
3. 数分待つと `にぎり寿司.app` ができます

**ビルド先は Unity プロジェクトの中に作らないでください。** Unity が
成果物を再インポートしようとして、無駄な時間がかかります。

---

## 6. 配布フォルダを組み立てる

デスクトップなどに `にぎり寿司` フォルダを作り、こう並べます。

```
にぎり寿司/
    にぎり寿司.app                      ← 5でビルドしたもの
    セットアップ.command
    はじめる.command
    カメラを選ぶ.command
    はじめにお読みください.txt
    ImageSearch/                        ← プロジェクトから丸ごとコピー
```

### ImageSearch から除いてよいもの

配布物を軽くするため、以下は削除して構いません。

```
TGS_sushi/          学習用の画像とラベル（約100MB）
runs/detect/train-2 〜 train-7    使わない学習結果
yolov8n.pt          学習の元にした素のモデル
train.py            学習用スクリプト
test.py test0.py main_test.py main_backup.py
_to_delete/
.venv/              配布先で作り直すので不要
```

**残すのは `runs/detect/train-6/weights/best.pt` だけ**で構いません。
`compare_models.py` を配布先で使わないなら、他の run は全て不要です。

### 実行権限を付ける

`.command` ファイルは、そのままでは「開けません」と言われます。
配布フォルダで一度だけ実行してください。

```bash
cd ~/Desktop/にぎり寿司
chmod +x *.command
```

これを忘れると、配布先でダブルクリックしても何も起きません。

## 7. 配布先の Mac での初回手順

### ⚠️ Gatekeeper の回避

署名していないアプリなので、macOS が起動をブロックします。
**配布先の人に必ず伝えてください。**

**アプリの場合**
`にぎり寿司.app` を**右クリック → 開く** → ダイアログの「開く」を押す。
ダブルクリックでは開けません。1回開けば以降は普通に起動できます。

**`.command` の場合**
同じく右クリック → 開く。

**まとめてブロックを外す方法**（確実）

```bash
xattr -dr com.apple.quarantine ~/Desktop/にぎり寿司
```

USB や AirDrop で渡すと `com.apple.quarantine` という印が付き、
これがブロックの原因になります。上のコマンドでフォルダごと外せます。

### セットアップ

1. `セットアップ.command` を右クリック → 開く
2. 5〜15分待つ（約2GB ダウンロードします）
3. 「セットアップが完了しました」と出れば OK

`python3 が見つかりません` と出た場合は、先にこれを実行してもらいます。

```bash
xcode-select --install
```

### カメラの設定

`カメラを選ぶ.command` を実行し、iPhone の映像が出たら `y` を押します。

**iPhone を使うので、配布先の Mac と iPhone が同じ Apple ID である必要があります。**
別の人の Mac で使うなら、その人の iPhone を連係カメラとして設定してもらいます。

### 起動

`はじめる.command` をダブルクリック。ターミナルが開き、画像認識が立ち上がり、
8秒後にゲームが起動します。**このターミナルは閉じないでください。**

## 8. 動作確認のチェックリスト

配布前に、必ずビルドした `.app` で確認してください。Editor で動いても
ビルドで動かない、ということが起こり得ます。

```
[ ] はじめる.command でターミナルが開き、カメラウィンドウが出る
[ ] ゲームがフルスクリーンで起動する
[ ] タイトルの「始め」でゲームが始まる
[ ] 注文が5個出る
[ ] ~/TGS_ImageSearch/order.txt に5行書かれる
[ ] ゲーム画面で Space を押すと、ターミナルに判定結果が出る
[ ] 1面 → WaitScene → 2面 → リザルト と進む
[ ] リザルトの得点が1面と2面の合計になっている
[ ] 「営業再開」でタイトルに戻る
[ ] 2周目の得点が 0 から始まる
[ ] ESC 長押しでアプリが終了する
[ ] 終了後、ターミナルの Python も一緒に終わっている
```

---

## 9. 展示当日の運用メモ

**起動の順番** — `はじめる.command` が全部やるので、これをダブルクリックするだけです。

**認識がおかしいとき** — ターミナルウィンドウで `a` / `s` キーを押すと、
手動で加点・減点できます。カメラウィンドウを選択してから押してください。

**カメラが繋がらないとき**
1. iPhone のロックを解除する
2. Mac の近くに置く
3. それでもダメなら `カメラを選ぶ.command` で選び直す

**アプリが終了しないとき** — ターミナルで `Control + C` を押すと、
Python もゲームもまとめて終了します。

---

## 10. 既知の制約

**Python 環境が必要** — 配布先の Mac で `セットアップ.command` を1回実行する
必要があります。約2GB のライブラリを入れるので、ネットワークが要ります。
これを避けたい場合は PyInstaller で Python ごと1つの実行ファイルにまとめる
方法もありますが、PyTorch を含むため 1GB を超える上、ビルドがかなり厄介です。
配布先が数台なら、セットアップ方式が現実的です。

**署名していない** — Apple Developer Program（年額）に加入して署名・公証すれば
右クリックが不要になりますが、身内での配布なら `xattr` で十分です。

**Windows では動きません** — 連係カメラが macOS 専用の機能です。
Windows に対応するなら、USB カメラか IP カメラに切り替える必要があります。
