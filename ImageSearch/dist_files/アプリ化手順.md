# にぎり寿司 — アプリケーション化の手順

展示機で `.app` として動かすまでの手順です。**作業時間は1時間ほど。**
初めてでも通せるように、順番どおりに書いてあります。

> **急ぐときは作らなくても構いません。** Unity の Game ビューを
> `Shift + Space` で最大化すれば、ほぼ同じ見た目で見せられます。
> ビルドで詰まって時間を失うより、そちらのほうが安全なこともあります。

---

## 0. 全体像

このゲームは **Unity 本体** と **画像認識（Python）** の2つが同時に動きます。
片方だけでは成立しないので、配布物は両方を含んだ1つのフォルダにします。

```
にぎり寿司/
    にぎり寿司.app            ← Unity のビルド
    セットアップ.command       ← 初回のみ実行（ライブラリを入れる）
    はじめる.command           ← 毎回これをダブルクリック
    カメラを選ぶ.command       ← カメラがずれたとき
    はじめにお読みください.txt
    ImageSearch/
        main.py
        camera_pick.py
        camera_check.py
        check_model.py
        config.example.json
        requirements.txt
        data.yaml
        models/best.pt        ← 採用中のモデル
        .venv/                ← セットアップ.command が作る
```

### 2つのプロセスがやりとりするもの

`~/TGS_ImageSearch/` に置かれます。**このフォルダはアプリの外**なので、
ビルドし直しても番付は消えません。

```
order.txt              Unity → Python   注文リスト
result.txt             Python → Unity   正解した貫数
capture_trigger.txt    Unity → Python   Space が押された合図
heartbeat.txt          Python → Unity   生きている印（1秒ごと）
countdown.txt          Python → Unity   自動判定のカウントダウン
ranking_見習い.json     Unity            モードごとの番付
ranking_板前.json
ranking_English.json
```

## 1. ビルド前のチェック（ここが一番大事）

**シーンに必要なものが入っていないと、ビルドしてから気づきます。**
Editor で通しプレイできていれば大丈夫ですが、念のため確認してください。

| シーン | 必要なもの |
|---|---|
| **SampleScene**（タイトル） | `QuitHandler` / `RankingBoard` / `ModeSelect` / `GameAudio` |
| **Game Scene**（1面） | `Customer` / `CaptureTrigger` |
| **Game Scene 2**（2面） | `Customer2` / `CaptureTrigger` |
| **Game Scene 3**（3面） | `Customer3` / `CaptureTrigger` |
| **ResultScene** | `ResultManager` / `TitleButton` |
| WaitScene | `WaitSceneManager` |

**`CaptureTrigger` は3つのゲームシーン全部に必要です。** これが無いと、
そのシーンだけ Space が効かず、自動判定のカウントダウンも出ません。

`QuitHandler` と `GameAudio` は `DontDestroyOnLoad` でシーンをまたいで
生き残るので、**タイトルに1つ置くだけ**で全シーンに効きます。

`ModeSelect` は **Canvas の子**に置いてください。

### 客の Inspector で確認すること

3つのゲームシーンすべてで、同じ設定になっているか見てください。

| 項目 | 値 |
|---|---|
| Order Sprites | 認識が確実なネタだけ。**モデルに無いネタを入れない** |
| Order Count | 3（お好みで） |
| Name Art | `OrderNameArt` アセット |
| Order Font | `NotoSansJP-Light SDF` |

**Order Sprites のファイル名は、YOLO のクラス名と完全一致**していないと、
何を置いても正解になりません。大文字小文字も区別されます。

### シーンの遷移先

| シーン | Next Scene Name | Scene After Wait |
|---|---|---|
| Game Scene | `WaitScene` | `Game Scene 2` |
| Game Scene 2 | `WaitScene` | `Game Scene 3` |
| Game Scene 3 | `ResultScene` | （使いません） |

## 2. Build Settings を整える

**File → Build Profiles**（古い Unity なら **File → Build Settings**）

### シーンの登録

`Scenes In Build` に6つ全て入っていて、**チェックが入っている**ことを確認します。
**一番上（index 0）が起動時に開くシーン**になります。

```
0  Scenes/SampleScene      ← タイトル。必ず先頭に
1  Scenes/Game Scene
2  Scenes/WaitScene
3  Scenes/Game Scene 2
4  Scenes/Game Scene 3
5  Scenes/ResultScene
```

**`Game Scene 3` の入れ忘れが一番ありがちです。**

### プラットフォーム

`macOS` を選び、必要なら **Switch Platform**。

**Architecture** は展示機が決まっているなら **Apple Silicon** で構いません
（ビルド時間が半分で済みます）。配る相手の Mac が不明なら Universal を。

---

## 3. Player Settings

Build Profiles の **Player Settings...** から開きます。

| 項目 | 設定 | 理由 |
|---|---|---|
| Company Name | 学校名や班名 | `.app` の識別子に使われます |
| Product Name | `にぎり寿司` | アプリ名として表示されます |
| Version | `1.0` | |
| Default Is Full Screen | ✅ オン | 展示用 |
| Default Screen Width / Height | `1920` / `1080` | |
| Mac Retina Support | ✅ オン | 文字がぼやけません |
| Resizable Window | オフ | 展示中に崩されないように |
| Display Resolution Dialog | Disabled | 起動時の設定画面を出さない |

**Icon** も設定できます。`Title.png` を指定すると Dock に出ます。

---

## 4. ビルドする

1. **Build**（`Build And Run` ではなく `Build`）
2. 保存先を聞かれるので、**デスクトップに新しい空フォルダ**を作って選ぶ
3. 数分待つと `にぎり寿司.app` ができます

> ⚠️ **ビルド先を Unity プロジェクトの中に作らないでください。**
> Unity が成果物を再インポートしようとして、無駄な時間がかかります。
> `.gitignore` で `*.app` を除外しているので、Git には乗りません。

---

## 5. 配布フォルダを組み立てる

デスクトップに `にぎり寿司` フォルダを作り、こう並べます。

```
にぎり寿司/
    にぎり寿司.app                  ← 4でビルドしたもの
    セットアップ.command             ┐
    はじめる.command                 │ ImageSearch/dist_files/
    カメラを選ぶ.command             │ からコピー
    はじめにお読みください.txt       ┘
    ImageSearch/                    ← プロジェクトから丸ごとコピー
```

### ImageSearch から除いてよいもの

配布物を軽くするため、以下は消して構いません。

```
TGS_sushi/          学習用の画像とラベル（約100MB）
runs/               学習結果。models/best.pt があれば不要
yolov8n.pt          学習の元にした素のモデル
train.py            学習用スクリプト
compare_models.py   モデル比較用
.venv/              配布先で作り直すので不要
```

**残すのは `models/best.pt` だけ**で構いません。

### 実行権限を付ける（忘れやすい）

`.command` ファイルは、そのままでは「開けません」と言われます。
組み立てたフォルダで一度だけ実行してください。

```bash
cd ~/Desktop/にぎり寿司
chmod +x *.command
```

**これを忘れると、ダブルクリックしても何も起きません。**

## 6. 初回の起動

### ⚠️ Gatekeeper の回避

署名していないアプリなので、macOS が起動をブロックします。

**まとめてブロックを外す**（これが確実です）

```bash
xattr -dr com.apple.quarantine ~/Desktop/にぎり寿司
```

USB や AirDrop で渡すと `com.apple.quarantine` という印が付き、
これがブロックの原因になります。上のコマンドでフォルダごと外せます。

個別にやるなら、`.app` と `.command` を**右クリック → 開く**。
ダブルクリックでは開けません。1回開けば以降は普通に起動できます。

### Python の準備

`セットアップ.command` を右クリック → 開く。5〜15分待ちます（約2GB）。

> **すでにシステムの python3 に ultralytics と opencv が入っている場合は、
> セットアップを飛ばせます。** `はじめる.command` は `.venv` が無ければ
> システムの python3 を使うようになっています。起動時に
> 「△ .venv がありませんが、システムの python3 で動かします」と出れば正常です。

`python3 が見つかりません` と出たら、先にこれを実行します。

```bash
xcode-select --install
```

### カメラの設定

`カメラを選ぶ.command` を実行し、iPhone の映像が出たら `y` を押します。

**iPhone を連係カメラとして使う場合、その Mac と iPhone が同じ Apple ID
である必要があります。** 展示機を替えるときはここを必ず確認してください。

他人のスマホを使うなら、Iriun Webcam などの仮想ウェブカメラアプリか、
USB カメラを使ってください。

### 起動

`はじめる.command` をダブルクリック。ターミナルが開き、画像認識が立ち上がり、
**準備ができ次第**ゲームが起動します。**このターミナルは閉じないでください。**

## 7. 動作確認のチェックリスト

**必ずビルドした `.app` で確認してください。** Editor で動いてもビルドで
動かない、ということが起こり得ます。

```
起動
[ ] はじめる.command でターミナルが開き、カメラウィンドウが出る
[ ] ゲームがフルスクリーンで起動する
[ ] タイトルに番付が表示される

モード選択
[ ] 「始め」でモード選択が出る
[ ] ボタンが画面からはみ出していない   ← 実行時に作るので要確認
[ ] 3つのモードそれぞれ選べる

ゲーム中
[ ] 注文が出そろうまで Space が効かない
[ ] 注文票が画面に出る（板前モードでは出ない）
[ ] 注文票が画面からはみ出していない   ← 実行時に作るので要確認
[ ] 寿司を置いて手を引くと「へい、お待ち！ 3 2 1」が出る
[ ] カウントダウン中に寿司を動かすと止まる
[ ] そのまま待つと判定され、次の面へ進む
[ ] 1面 → 待機 → 2面 → 待機 → 3面 → リザルト

リザルト
[ ] 明細が上から1行ずつ出る
[ ] 右側に合計が数え上がって出る
[ ] 売上に応じた音が鳴る
[ ] タイトルに戻ると番付に載っている
[ ] 2周目の売上が 0 から始まる

終了
[ ] ESC 長押しでアプリが終了する
[ ] 終了後、ターミナルの Python も一緒に終わっている
```

**「実行時に作る」と書いた2項目**（モード選択・注文票）は、
エディタとビルドで見え方が変わる可能性がある場所です。**重点的に見てください。**

## 8. 展示当日の運用

### 起動

`はじめる.command` をダブルクリックするだけです。

### 係員用のキー（ゲーム画面で）

| 操作 | 効果 | どこで |
|---|---|---|
| **Ctrl + Shift + R** 長押し | 番付を全消し（3モードとも） | タイトル画面 |
| **Ctrl + Shift + N** | その面を 0貫 として飛ばす | ゲーム画面 |
| **ESC** 長押し | アプリを終了 | どこでも |

朝いちばんに **Ctrl + Shift + R** で番付をリセットしてください。

### カメラ画面（ターミナル側）のキー

**フルスクリーンだとカメラ画面は裏に隠れます。** 使うときは `Cmd + Tab` で
前に出してください。**通常の運用では触る必要はありません。**

| キー | 効果 |
|---|---|
| `t` | 自動判定の ON / OFF |
| `a` / `s` | 手動カウンタ +1 / −1 |
| `Enter` | 手動カウンタを確定して送信 |
| `Space` | すぐ判定 |

**認識がどうしても合わないとき**は、`a` を正解数ぶん押してから `Enter`。
押しただけでは送信されないので、落ち着いて数を作ってください。

### よくあるトラブル

**画面に「画像認識が停止しています」と出た**
Python が落ちています。ターミナルを確認し、`はじめる.command` を
やり直してください。復旧できなければ **Ctrl + Shift + N** で先へ進めます。

**カメラが映らない**
1. iPhone のロックを解除し、Mac の近くに置く
2. Wi-Fi と Bluetooth を両方オンにする
3. それでもダメなら `カメラを選ぶ.command` で選び直す
4. 裏で Python が生き残っていることがあります → `pkill -f main.py`

**自動判定が始まらない**
注文の数だけ置かれているか確認してください。カメラ画面に
`AUTO: placed 3/5` と出ていれば、まだ足りていません。
急ぐときは Space で判定できます。

**自動判定が早すぎる／遅すぎる**
`ImageSearch/config.json` を編集して、`はじめる.command` を再起動します。

```json
"auto_stable_seconds": 2.0,        ← 静止と判断するまでの秒数
"auto_countdown_seconds": 3.0,     ← カウントダウンの長さ
"auto_judge": false                ← 自動判定を完全に切る
```

## 9. モデルを差し替えるとき

画像認識班から新しい `best.pt` を受け取ったら、**組み込む前に必ず**
照合してください。クラス名がズレていると、検出はできるのに全部不正解
という、気づきにくい事故になります。

```bash
cd ImageSearch
python3 check_model.py ~/Downloads/best.pt
```

「✅ 問題なし」が出たら差し替えます。**`data.yaml` も一緒に**受け取って、
同じように差し替えてください。モデルと data.yaml は必ずセットです。

```bash
cp ~/Downloads/best.pt models/best.pt
cp ~/Downloads/data.yaml data.yaml
```

**ビルドし直す必要はありません。** モデルは `.app` の外にあるので、
ファイルを置き換えて `はじめる.command` を再起動するだけです。

### クラスが変わった場合は Unity 側も

1. 新しいクラス名と同じ名前のスプライトを `Assets/OrderSprites/` に用意
2. 3つのシーンの **Order Sprites** を入れ替え
3. **OrderNameArt** に文字画像を登録
4. `GameMode.cs` の漢字・カタカナ・英語の表に追加（画像が無いとき用の保険）

**モデルに無いネタを Order Sprites に残さないでください。** 出た瞬間に
絶対不正解になります。

## 10. 既知の制約

**Python 環境が必要**
配布先の Mac に ultralytics と opencv が要ります。`セットアップ.command`
で入りますが、約2GB のダウンロードが発生します。PyInstaller で1つに
まとめる方法もありますが、PyTorch を含むため 1GB を超える上、ビルドが
かなり厄介です。数台なら今の方式が現実的です。

**署名していない**
Apple Developer Program（年額）に加入して署名・公証すれば右クリックが
不要になりますが、身内での配布なら `xattr` で十分です。

**連係カメラは macOS 専用**
Windows に対応するなら、USB カメラか IP カメラに切り替える必要があります。

---

## 11. 保険

**ビルド担当が当日来られないと詰みます。**

別の1人が、一度だけ練習でビルドを通してみてください。**1時間ほどで
終わり、この手順書の不備もそこで見つかります。** 当日にぶっつけで
やることだけは避けてください。

そしてもう一つ。**ビルドが間に合わなくても、Unity の Game ビューを
`Shift + Space` で最大化すれば見せられます。** これを知っているだけで、
当日の焦り方が変わります。
